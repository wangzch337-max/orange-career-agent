# 聊天式自适应职业画像

用户看到的是一个连续的 Orange 对话：上传简历、查看初步理解、选择「继续完善我的职业画像」、在同一个聊天输入框回答问题，然后审阅「我的职业画像」。不需要理解内部阶段，也没有另一个补充表单。语气面向学生，但不假设专业、实习需求、技术背景或项目经验；工作经历始终是一等证据。

## 会话协调与停止

`career_runtime/profile_conversation.py` 只协调既有 Clarification / Profile Refinement 接口，不复制证据推理或确认逻辑。每次用户回答后，用既有确定性 needs 重新判断是否还有重要问题。没有重要问题就整理画像；明确不确定也是有效信息，跳过不补造答案。最多四次问题选择，通常更早停止。达到上限仍未说明的事项保持待了解，不为了填满字段继续问。

每个回答至多触发一次问题选择。通常只有一次语义调用：下一问题选择或画像建议生成。若选择器已发出经过校验的「不再提问」决定，则只允许一次后续画像建议生成；不存在模型循环、judge、修复或自动重试。只有按钮和聊天提交触发操作，渲染、主题切换与刷新不触发模型。

## 权限与隐私

简历分析同意仍独立且明确。「继续完善」旁说明 Qwen 将接收必要的精简简历证据、已确认信息、相关记忆和回答；这个操作只授权本次画像对话，不开启普通 AI 聊天。画像审阅是临时理解，只有「确认这份职业画像」才走原有确认路径。整份确认只处理所展示的变更，保留不确定性，并继续执行来源、版本和 owner/thread 校验。不同于旧画像的内容会显示原理解，用户可保留原值或暂不采纳。

简历、问题、回答、审阅卡片使用内存中的临时时间线，并与普通聊天位置交错；不序列化进聊天数据库或 snapshot，不新增 transcript-to-Memory 写入。普通问答仍走已有路径，需要原有独立 AI 同意。画像确认不隐式开启长期记忆保存，现有后端可选记忆权限不变。

## 修改、失败和生命周期

「我想修改」或「继续聊聊」让用户在普通输入框补充；新建议仍经过原有校验，不直接覆盖旧画像。失败只显示自然、安全的说明，回答只保留在当前会话，不声称已持久保存；结构化错误码仅留在安全事件中，无自动重试。

普通问答不作为画像答案。回答完成后的同线程刷新仅在会话绑定仍有效时保留临时画像流程。新对话、切换、删除、替换简历、撤回同意及关闭会话均清理临时状态；迟到结果不能恢复被删除的状态。D.1 仍是确认之后的下游探索组件，未改变语义，也未实现 D.2。

## 人工验收与学习

Codex 负责会话协调、主时间线展示、有限调用和离线权限回归。可选亲手任务：用公共合成简历走一次「不确定 → 修改 → 明确确认」，检查浅／深色模式中没有脱离聊天的表单。关键概念：聊天式展示不等于持久化权限，临时理解不等于已确认画像。验收问题：为什么普通问答可以持久化，而这次画像回答仍留在临时会话？人工流程审阅前停止，不进入 D.2。

## 集成冻结的验证边界

本里程碑用完整离线回归、确定性外部评价、公开文件与可达历史安全扫描冻结现有行为，不实现新功能。ResumeEvidence 已有有限真实 Qwen 验证和公开合成生产路径 smoke；最新修复与 UX 集成后的完整 Clarification → Profile 链尚未重新完成真实 Qwen 端到端验证。真实 provider 的物理取消／Stop wall-clock 恢复仍是验证缺口；Fake 与 AppTest 通过不能替代这些 live 结论。本次 live calls = 0，后续验证须另获单独授权。
